# Описание (заметки) процесса создания среды разработки и анализа в проекте

## 1. Создаем \ пересоздаем проект "с нуля"
Для управления зависмостями в проекте используется инструмент - `uv`, для сконтроля изменений и синхронизации с репозиторием в облаке - `git`.  
### Установка `uv` 
Самый быстрый и простой способ закачать при помощи `curl` и одновременно запустить универсальный скрипт.

Для linux: 

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh 
```
После установки перезапустите терминал или выполните 
```bash
source ~/.bashrc
```
чтобы команда `uv` стала доступна.

Для Windows:

```bash
powershell -ExecutionPolicy Bypass -c "irm https://releases.astral.sh/github/uv/releases/download/0.13.9/uv-installer.ps1 | iex"
```
Этот же скрипт, при необходимости - обновит инструмент `uv`. При запуске скрипт проверяет уже установленную версию `uv`.   

Если хочется безопасности, контрольных сумм - добро пожаловать [скачивать релизы с github](https://github.com/astral-sh/uv/releases) распаковывать архивы и проверять посредством `SHA256SUM`.

Может так случится, что в системе не установлена команда `curl`. Если это так, то можно установить его с помощью команд:
1. Обновление списка пакетов.
```bash
sudo apt update
```
2. Установка `curl`.
```bash

sudo apt install curl
```
3. Проверить установку curl:
```bash
curl --version
```

## Установка git
1. Обновление списка пакетов.
```bash
sudo apt update
```
2. Установка `git`. 

```bash
sudo apt install git
```
Лучше всего устанавливать `git` в систему, т.к. он применяется во многих проектах. Поэтому, на данном этапе установка должна происходить без активации виртуального окружения. Эта команда - найдет пакет `git` в репозиториях и установит его вместе со всеми необходимыми зависимостями.

3. Проверка установки. 
```bash
git --version
```
## Создание папки проекта и инициализация uv и git управления 
На данном этапе, нужно чтобы рабочая папка была той, в которой хранятся папки аналогичных проектов(родительской для папки проекта). Выполняем в терминале:

```bash
uv init ai_engineer_preproject --python 3.12 && cd ai_engineer_preproject 
```
Эта команда еще и закрепит в проекте используемую версию python. 
Можно инициировать и существующую (предварительно созданную) папку. В этом случае в созданную папку проекта нужно перейти командой `cd`. Команда инициализации уже будет выглядеть так:
```bash
uv init
```
## Создание виртуального окружения и активацие его

```bash
uv sync
source .venv/bin/activate
```
В принципе, при управлении проектом `uv` - не обязательно активировать виртуальное окружение, `uv` будет это делать автоматически, во всех случаях, когда это требуется. Но при использовании `VS Code`, лучше, чтобы оно было запущено в среде активированного виртуального окружения.


## Добавим еще нужных папок в структуры проекта:

```bash
mkdir -p notebooks src/ai_engineer_preproject scripts
```
Тоже самое можно делать в интерфейсе Vs Code


Теперь добавим в pyproject.toml зависимости, необходимые для работы с Jupyter и MCP-серверами, а также настроим VSCode. 

```bash
uv add jupyterlab ipython fastmcp
```
Синхронизируем зависимости (действие, которое делается всегда после изменения настроек зависимостей)

```bash
uv sync
```
## Настроим VSCode.
Чтобы ноутбуки и код использовали созданное `uv`-окружение:
```bash
mkdir -p .vscode && cat > .vscode/settings.json << 'EOF'
{
    "python.defaultInterpreterPath": "${workspaceFolder}/.venv/bin/python",
    "python.terminal.activateEnvironment": true,
    "notebook.kernelSources": [
        {
            "name": "ai_engineer_preproject (uv)",
            "path": "${workspaceFolder}/.venv/bin/python"
        }
    ],
    "files.exclude": {
        "**/__pycache__": true,
        "**/.mypy_cache": true,
        "**/.pytest_cache": true,
        "**/.ipynb_checkpoints": true
    }
}
EOF
```
Сделаем синхронизацию зависимостей:
```bash
uv sync
```

## Синхронизация с GitHub

На данном этапе папка проекта уже будет иметь инициирование git - это делает `uv` на предыдущем этапе. Создается папка `.git` и структура в ней,также создается файл `.gitignore` (список файлов, которые не должны быть добавлены в репозиторий)

### Синхронизация с локальным репозиторием проекта

На данном этапе, добавлять изменения (имена файлов, которые изменились) в коммиты уже можно.

Но сами коммиты можно делать, когда git знает - кто автор изменений. Нужно настроить имя пользователя и его email. Это делается командами:
```bash
git config user.name "Z0rinSerg"
git config user.email "sr.z0rs@gmail.com"
```
### Сделаем первый коммит
Добавим в коммит все файлы:

```bash
git add .
```
Посмотреть статус перед коммитом:
```bash
git status
```
Необходимо обратить внимание на имя ветки (branch). Оно должно быть `main` - именно так называется ветка в облачном репозитории. Если это не так, нужно переименовать ветку:
```bash
git branch -m master main
```

Теперь можно сделать первый коммит:
```bash
git commit -m "feat: My first, initial commit"
```
### Проверим состояние в логах

```bash
git log --oneline
```
должно быть что-то такое:
```
a9dbb48 (HEAD -> main) feat: My first, initial commit
```
Локальная синхронизация настроена

### Синхронизация с облаком (GitHub)
Для сихронизации с `GitHub` нужно чтобы у авторизованного пользователя был репозиторий с именем `ai_engineer_preproject` . Совпадение с именем папки проекта на локальной платформе с именем облачного репозитория - все упрощает, но в принципе можно настроить и по-другому. 

Простейший способ создать репозиторий - воспользоваться интерфейсом web-сервера GitHub. 
(Создание - здесь не описывется). Также требуется создание и регистрция SSH ключа для доступа к GitHub посредством ssh-протокола.

После создания репозитория в GitHub, нужно добавить ссылку на этот репозиторий в локальную систему. Для этого нужно выполнить следующие команды:
```bash
git remote add origin git@github.com:Z0rinSerg/ai_engineer_preproject.git
```

После этого можно локальные коммиты отправить в облачный репозиторий. В первый раз команда должна выглядеть так:
```bash
git push -u origin main
```
Это не только зальет локальные соммиты на облачный репозиторий, но и установить восходящую связь локального репозитория с облачным. 
В последствии можно использовать простую команду: 
```bash
git push
```
Это просто отправит все локальные коммиты в облачный репозиторий. 

# 2. Воссоздаем на другой платформа или после краша

### Первичная синхронизация в локальной новой среде 

В случае, когда проект не создается заново "с нуля", а создается или пересоздается локальная среда разработки для данного проекта, и облачный репозиторий существует - нужно синхронизировать локальную систему с облачным репозиторием. 

Из инструкций выше нужн выполнить те, которые устанавливают `git` и `uv`. 

Затем, клонировать папку проекта из облачного репозитория на локальную платформу. Предполагается, что папки проекта не существует, рабочая папка дананном этапе это такая, в которой будет находится папка проекта. 
Для клонирования необходимо выполнить следующие команды:

```bash
git clone https://github.com/Z0rinSerg/ai_engineer_preproject
```
Перейти в папку проекта: 
```bash
cd ai_engineer_preproject 
```
Затем необходимо синхронизировать среду python c зависимостями, т.к. они не синхронизируются с облачным репозиторием и соответсвтвенно не закачиваются при клонировании. Необходимо выполнить команду: 
```bash
uv sync
```
Это закачает необходимую версию `python` и необходимые зависимости с требуемыми версиями, в соответсвии с `pyproject.toml` и `uv.lock` 

Проверить настройи git на синхронизацию с удаленным репозиторием:
```bash
git config --list --show-origin
```
Настроить на доступ к github по ssh:
```bash
git remote add origin git@github.com:Z0rinSerg/ai_engineer_preproject.git
```
Также потребуется генерация (или копирование с платформы, где они уже работают - но это не безопасно!) ключей и регистрация их на github. 

### Синхронизация локальной системы с облачной 
При ежедневной работе и перемещении между платформами между локациями необходимо:
- Для синхронизации облачного репозитория с локальной системой - при завершении работы на одной платформе :
    - Сохранить все изменения в файлах : `Vs Code -> Menu File -> Save all`
    - Выбрать конкретные файлы для коммита или все: `Vs Code -> Extension Git -> Changes -> ` `+` 
    - Сделать коммит `Vs Code -> Extension Git -> Commit` (заполнить поле message)
    - Отправить коммит на удаленный репозиторий: `Vs Code -> Extension Git -> Push`      
- Для синхронизации локальной системы с облачным репозиторием при старте работы на другой платформе :
    - затянуть изменения на локальную платформу:
    ```bash
    git pull
    ```
    - синхронизировать зависимости:
    ```bash
    uv sync
    ```

## Файл отличий платформ .env 
В проекте испольуется файл `.env` для хранения переменных среды. В зависимости от платформы, в файле будут разные значения переменных среды. 
Это пока является "костылем" и нужно будет доработать в будущем - возможно убрать данный механизм вообще. Имя файла .env находится в исключениях git - gitignore.

### Записи в .env
Пример записи в `.env`:
```
OLLAMA_URL = "http://localhost:11434"
```
### Описание переменных в .env
|Переменная| Тип| Описание|
|---|---|---|
PROJECT_ROOT| str| Путь к корневому каталогу проекта|
OLLAMA_DOCS| str| Путь к директории с документацией (датасет) Ollama| 
OLLAMA_URL| str| URL для доступа к сервису Ollama|
