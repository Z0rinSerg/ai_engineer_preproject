В современной разработке для структурирования истории коммитов в Git чаще всего используется стандарт **Conventional Commits**. Его суть в том, что сообщение начинается с префикса, который обозначает тип изменения, затем ставится двоеточие и краткое описание. Это делает историю коммитов машиночитаемой, что позволяет автоматически генерировать *changelog* (журнал изменений) и определять версию пакета.

Ниже приведен список наиболее распространенных префиксов из этой спецификации.

| Префикс | Значение | Пример использования |
| :--- | :--- | :--- |
| **feat:** | Добавление новой функциональности (фичи) для пользователя. | `feat(auth): add JWT authentication` |
| **fix:** | Исправление ошибки (бага). | `fix(api): handle division by zero` |
| **docs:** | Изменения только в документации (README, комментарии в коде). | `docs: update project setup guide` |
| **style:** | Правки форматирования, отступов, точек с запятой — всё, что не меняет логику кода. | `style: reformat code according to PEP8` |
| **refactor:** | Изменение кода, которое не исправляет ошибку и не добавляет функцию (например, переименование переменной). | `refactor: extract validation to service` |
| **perf:** | Изменение кода, которое улучшает производительность. | `perf(db): add index to user_email` |
| **test:** | Добавление или исправление тестов. | `test: cover edge cases in parser` |
| **build:** | Изменения, влияющие на систему сборки или внешние зависимости. | `build: upgrade webpack to v5` |
| **ci:** | Изменения в файлах и скриптах конфигурации CI/CD. | `ci: update github actions workflow` |
| **chore:** | Рутинные задачи, не подходящие под другие типы (например, обновление зависимостей `package-lock.json`). | `chore: bump version to 1.2.0` |
| **revert:** | Отмена предыдущего коммита. | `revert: feat: add password recovery` |

**Нюансы использования:**
*   **Область (scope):** В скобках после префикса можно указать затронутую часть системы, например `feat(api)` или `fix(ui)`. Это помогает быстрее понять контекст изменения.
*   **Язык:** Хотя английский является стандартом *de facto* для коммитов, спецификация не запрещает использовать русский язык, если вся команда договорилась об этом. Главное — соблюдать единый стиль.
*   **Формат:** После префикса (и области) обязательно ставится двоеточие и пробел. Само сообщение принято писать в повелительном наклонении (например, *Add* вместо *Added*).

Помимо этого, существует расширенный список префиксов, который иногда встречается в строгих корпоративных стандартах. Он включает типы вроде `wip` (work in progress), `types` (изменения типов в TypeScript) или `workflow` (изменения в процессах разработки). [sources=[1, 2, 3, 4]]
