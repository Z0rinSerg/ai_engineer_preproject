## ИИ-инженер (AI Engineer)

```
Это специалист, который проектирует системы на основе готовых языковых моделей:
собирает вокруг них инфраструктуру, пайплайны работы с данными, интеграции и инструменты оценки качества. 
```
Что это означает на деле:

* Пайплайны работы с LLM: поиск релевантной информации, управление контекстом, промптинг, постобработка ответов.
* Интеграция моделей с внешними источниками (документами, базами знаний, API).
* Настройка инференса и итеративное улучшение качества ответов.
* Выбор стека: облачный провайдер или локальное развёртывание, тип эмбеддингов, векторная база.

С готовыми ML- и DL-моделями работают несколько профессий — от классических разработчиков до дата-сайентиста, ML-инженера и ИИ-инженера, — но делают это по-разному. Основной инструмент ИИ-инженера — уже обученная LLM.

# Локальная среда разработки VS Code
Задания курса вы будете выполнять локально, на своём устройстве — так же, как это делают ИИ-инженеры в реальных проектах. Для этого нужно настроить локальную среду разработки — Visual Studio Code (VS Code). Это бесплатный кроссплатформенный редактор кода от Microsoft, доступный на Windows, macOS и Linux.
VS Code особенно удобен для Python-разработки: поддерживает расширения для Python и Jupyter-ноутбуков, а встроенный терминал позволяет выполнять команды прямо в окне редактора.

## Установка VS Code и расширения Python

1. Перейдите на официальный сайт. Выберите установщик для вашей ОС и скачайте его.
2. Запустите установщик и следуйте инструкциям. По завершении откройте VS Code.
3. Добавьте поддержку Python и Jupyter. Для этого откройте меню Extensions (иконка квадратов в боковой панели) и установите расширение Python от Microsoft.
4. После установки перезапустите VS Code. Теперь он готов к работе с проектами на Python.

## Python и виртуальное окружение
Для работы с проектом понадобится Python версии 3.10 или выше (использую 3.12 для совместимости платформ в разных локах). Если он не установлен — скачайте его. При установке на Windows обязательно поставьте галочку "Add Python to PATH".
Проверить установку можно в терминале: 
```bash
python --version
```
Ожидаемый вывод — что-то вроде ```Python 3.12.3```

Дальше создадим виртуальное окружение. Оно изолирует библиотеки этого проекта от других проектов на вашем компьютере — зависимости не будут конфликтовать между собой.
### Создание окружения

В терминале перейдите в папку, где будете хранить проект (например, создайте новую — ai_assistant_free_track), и выполните:
```
python3 -m venv .venv   # для macOS/Linux
python -m venv .venv    # для Windows 
```
Это создаст папку ```.venv``` с копией выбранного интерпретатора Python.

### Активация окружения

В VS Code откройте терминал (View — Terminal) и выполните:

```
# на macOS/Linux:
source .venv/bin/activate

# на Windows:
.\.venv\Scripts\activate 
```
После активации вы увидите ```(.venv)``` перед командной строкой.

### Установка пакетов
В терминале с активированным ```.venv```  выполните:
```bash
pip install requests numpy sentence-transformers faiss-cpu pypdf 
```
Это установит все библиотеки, необходимые для курса: ```requests```, ```numpy```, ```sentence-transformers```, ```faiss-cpu``` и ```pypdf```.

## Работа с Jupyter Notebook в VS Code

Расширение Python от Microsoft уже включает поддержку Jupyter-ноутбуков — отдельно ничего ставить не нужно. Jupyter удобен для пошаговых экспериментов: вы можете чередовать ячейки с кодом и комментариями, видеть результат каждого шага и быстро переподключать переменные.

# Что такое RAG и как устроен ИИ-ассистент

В предыдущем уроке вы познакомились с ролью ИИ-инженера и настроили локальное рабочее место. Теперь всё готово для того, чтобы начать разбираться с архитектурой!

В этом уроке разберёмся, почему «просто LLM» не справляется и что именно ломается, как устроена RAG-система и из каких компонентов состоит, как выглядит пайплайн от вопроса пользователя до ответа. Заодно зафиксируем целевой вид функции-ассистента и подготовим окружение: установим Ollama, скачаем модель и датасет.

Казалось бы, всё просто: берём мощную языковую модель и задаём ей вопрос.

Разработчик спрашивает у «чистой» LLM: «Какой HTTP-метод использует эндпоинт ```/api/generate``` в Ollama и какие параметры обязательны?»
Модель отвечает убедительно — и, скорее всего, не совсем верно: имена полей могут быть выдуманными, обязательность параметров перепутанной, а возможностей, появившихся после даты обучения, не быть вовсе.
Когда LLM выдаёт уверенный, но неверный ответ — это галлюцинация. Для продуктовой системы это проблема: ассистент не должен выдумывать сигнатуры API, формат ```modelfile.mdx``` или шаги ```troubleshooting.mdx```.

Проблему можно решить двумя способами:

1. Дообучить модель на документации Ollama (это дорого, долго и требует повторного обучения при каждом обновлении документации).
2. Давать модели нужную информацию в виде контекста прямо в запросе. Тогда она не будет «вспоминать», а ответит, опираясь на приложенные документы.

Второй путь называется RAG. Его и будем собирать.

``` 
RAG (Retrieval-Augmented Generation) — подход, при котором LLM отвечает не «из памяти», а на основе документов, найденных системой под конкретный запрос пользователя.
```
Расшифруем: Retrieval — поиск, Augmented — обогащение, Generation — генерация. Итого: генерация, обогащённая поиском.

RAG-система обычно выглядит как цепочка из нескольких шагов: сначала мы заранее готовим базу знаний, а потом используем её для ответа на вопрос пользователя. Сначала посмотрим на общую схему целиком, а уже затем разберём, из каких компонентов она состоит.

# Компоненты RAG-системы

RAG-система состоит из четырёх базовых частей: чанкинга, эмбеддингов, векторного поиска и промптинга с инференсом LLM. Это именно строительные блоки системы — то, из чего она собрана.
Отдельно от компонентов стоит пайплайн — порядок, в котором эти части работают при загрузке документов и ответе на запрос.
## 1. Чанкинг

Документы обычно длинные: в документации Ollama файл api.md — это десятки страниц, modelfile.md — ещё столько же. Подавать их в модель целиком нельзя по двум причинам.
Во-первых, у LLM ограничен размер контекстного окна — количество токенов, которое модель может обработать за один раз. Во-вторых, даже если документ помещается, поиск по нему целиком менее точен, чем по небольшим фрагментам: нужное легко теряется в длинном тексте.
Поэтому документы разбивают на чанки — смысловые фрагменты по 200–500 слов. Хорошо подобранный чанк содержит одну законченную мысль: описание одного эндпоинта, правило одного параметра Modelfile, ответ на один FAQ.
Результат этого этапа — список чанков, который хранится в файле или в базе и ждёт, когда его будут искать.

# Датасет: документация Ollama
В качестве базы знаний для нашего ассистента возьмём официальную документацию Ollama, она лежит в открытом доступе на GitHub. Это хорошо структурированный набор документов: описание API, FAQ, диагностика, инструкции по установке — всё то, что встречается в реальных RAG-проектах.
Скачать датасет можно двумя способами — выбирайте наиболее удобный.
## Способ 1. Готовый архив
Мы заранее скачали папку docs/ из репозитория Ollama и упаковали её в архив. Просто скачайте и распакуйте его в папку проекта — туда же, где лежит .venv. Должна появиться папка docs/ с документами внутри.
docs.zip-архив с папкой docs/ из репозитория github.com/ollama/ollama.
## Способ 2. Через Git
Если у вас установлен git, можно забрать папку прямо из репозитория. Перейдите в папку проекта и выполните:
```bash
git clone --depth 1 https://github.com/ollama/ollama.git temp_ollama 

```
Команда скачает свежий снимок репозитория без истории коммитов (ключ --depth 1 ускоряет скачивание). Дальше можете оставить только папку docs, с которой мы и будем работать. (ollama_docs)
Большая часть файлов имеет расширение .mdx — это тот же Markdown, но с поддержкой JSX-вставок. Для наших целей разница незначительная: .mdx мы будем читать так же, как обычные .md-файлы. Если вы скачивали через Git, в папке также могут быть служебные файлы (.svg-логотипы, .css-стили).
